# Lunch Window Prediction

Расчёт перелёта Земля → Луна для задачи **NASA Space Apps Challenge 2026 — Lunar Landing Site Navigator**.

Программа по дате старта находит даты прилёта и посадки, и наоборот: по дате посадки находит дату старта.
Точка посадки (широта и долгота на Луне) определяет даты. Если сесть нельзя, программа объясняет почему:
нет Солнца или Земли над горизонтом, слишком крутой рельеф, не хватает Δv, нет окна старта и т. п.

- **11 космодромов** с их ограничениями азимутов и наклонений (`data/spaceports.toml`).
- **Ракеты и лунные аппараты:** готовые пресеты и переопределение любых параметров.
- **Выбор траектории** (`--trajectory`): прямой перелёт (`direct`, по умолчанию — задача Ламберта при любом угле
  перелёта) или перелёт Гомана (`hohmann` — разгон по касательной в перигее, апогей у Луны, 180°). Сначала поиск
  по формулам (patched conic), затем численное уточнение лучшего варианта: интегратор Dormand–Prince, поле
  тяготения Луны GRAIL до степени 60, сжатие Земли, притяжение Солнца, разгон к Луне конечной тягой, спуск
  с торможением.
- **Режим полёта** (`--mode`): быстрый (`fast`, по умолчанию — лучший вариант в заданные сутки, как раньше)
  или экономный (`economy` — наименьший суммарный Δv миссии: разгон + торможение + спуск; более широкие пределы
  времени перелёта и ожидания на окололунной орбите, несколько наклонений опорной орбиты и поиск в пределах
  ±N суток от заданной даты). Параметры экономного режима — секция `[economy]` в `data/transfer.toml`.
- **Окно старта** (`--launch-window`, по умолчанию выключено): вместо одного варианта — все моменты старта,
  при которых посадка в заданные сутки (`--arrival-date`) обходится не дороже наименьшего суммарного Δv миссии
  плюс запас (`--window-margin`, по умолчанию 50 м/с). Ищется только по дате посадки; параметры — секция
  `[launch_window]` в `data/transfer.toml`.
- **Проверка площадки** по рельефу LOLA (уклоны, перепад высот, горизонт) и видимость Солнца и Земли из точки посадки.
- **Журналы в JSON:** траектория для 3D-визуализации и читаемый журнал полёта.
- **API для других программ:** JSON через командную строку, расчёты фоновыми задачами.

Эфемериды и системы координат дают [ANISE](https://github.com/nyx-space/anise) и ядра NAIF (DE440).

## Быстрый старт

Нужен Rust 1.85 или новее (edition 2024).

```bash
cargo build --release
```

Посадка на Южный полюс Луны 14 февраля 2027, старт с Байконура на «Союзе-2.1б» с «Фрегатом»:

```bash
target/release/launch-window-prediction --kernels-dir data/kernels \
  --arrival-date 2027-02-14 --spaceport baikonur --rocket soyuz_21b_fregat --lat -89.0 --lon 45
```

Лучший старт 29 декабря 2026 со всех подходящих космодромов, без точки посадки:

```bash
target/release/launch-window-prediction --kernels-dir data/kernels --launch-date 2026-12-29
```

С проверкой рельефа (нужны карты LOLA, см. ниже) и лунным аппаратом:

```bash
target/release/launch-window-prediction --kernels-dir data/kernels --terrain-dir data/terrain \
  --arrival-date 2027-01-01 --spaceport ksc --rocket sls_block1 --spacecraft apollo_lm_descent \
  --lat 5 --lon -10
```

Тот же старт по траектории Гомана:

```bash
target/release/launch-window-prediction --kernels-dir data/kernels --launch-date 2026-12-29 --trajectory hohmann
```

Экономный режим: самый экономичный по топливу вариант в пределах ±3 суток от даты (в выводе — выбранные
сутки у каждого космодрома, экономия по сравнению с заданными сутками и Δv миссии по каждым суткам):

```bash
target/release/launch-window-prediction --kernels-dir data/kernels --arrival-date 2027-02-14 --lat 0.674 --lon 23.473 --mode economy
```

Экономный режим считает 2N+1 суток (по умолчанию 7), поэтому идёт дольше быстрого. Если в заданные сутки
вариантов нет (например, в точке посадки нет подходящего освещения), он находит ближайшие сутки, где они есть.

Окно старта для посадки в заданные сутки (вместо быстрого и экономного режима): когда окно открывается и
закрывается, из каких интервалов состоит, где внутри наименьший Δv миссии:

```bash
target/release/launch-window-prediction --kernels-dir data/kernels --spaceport ksc --arrival-date 2027-02-13 --lat 0.674 --lon 23.473 --launch-window
```

Края окна — моменты старта, при которых суммарный Δv миссии (разгон + торможение + спуск) становится больше
наименьшего на `--window-margin` м/с (по умолчанию 50). Окно считается по формулам с шагом прилёта 10 минут
и по умолчанию не уточняется численно (секунды работы на вариант, на края окна это не влияет); чтобы уточнить
самый экономный вариант, задайте `[launch_window] refine = true`. С `--launch-date` окно не ищется.

Все параметры: `launch-window-prediction --help`. Список аппаратов: `--list-spacecraft`.
Параметр ракеты или аппарата переопределяется так: `--rk payload_tli_kg=9000`, `--sc payload_mass_kg=0`.

## Данные

| Папка | Что внутри | В репозитории |
|---|---|---|
| `data/kernels/` | ядра эфемерид: `de440s.bsp`, `moon_pa_de440_200625.bpc`, `moon_fk_de440.epa`, `earth_latest_high_prec.bpc`, `pck11.pca` (~51 МБ) | да |
| `data/gravity/` | поле тяготения Луны GRAIL GL0660B до степени 60 | да |
| `data/terrain/` | карты высот LOLA: описания `.LBL` | да |
| `data/terrain/*.IMG` | сами карты высот (115–530 МБ каждая) | **нет**, скачиваются скриптом |
| `data/*.toml` | космодромы, ракеты, аппараты, параметры перелёта, посадки, видимости | да |

Ориентация Земли `earth_latest_high_prec.bpc` (ITRF93) покрывает даты примерно до февраля 2027.
Для более поздних дат программа сама переходит на модель IAU_EARTH. Свежее ядро можно скачать флагом
`--download-kernels` (нужен интернет).

### Карты рельефа LOLA

Без карт программа работает, но не проверяет площадку и считает горизонт ровным.
Карты скачивает скрипт — в `data/terrain/`, рядом с одноимёнными `.LBL`:

```powershell
# Windows (PowerShell)
powershell -ExecutionPolicy Bypass -File scripts\download_terrain.ps1               # все карты, ~1,2 ГБ
powershell -ExecutionPolicy Bypass -File scripts\download_terrain.ps1 global south  # только выбранные
```

```bash
# Linux / macOS
scripts/download_terrain.sh                 # все карты
scripts/download_terrain.sh global south    # только выбранные
```

| Ключ | Файл | Покрытие | Размер |
|---|---|---|---|
| `global` | `LDEM_64.IMG` | вся Луна, 64 пикс./град (~474 м) | 531 МБ |
| `south` | `LDEM_80S_80M.IMG` | южная полярная область от 80° ю. ш., 80 м | 116 МБ |
| `north` | `LDEM_80N_80M.IMG` | северная полярная область от 80° с. ш., 80 м | 116 МБ |
| `south10m` | `LDEM_875S_10M.IMG` | окрестность Южного полюса от 87,5° ю. ш., 10 м | 460 МБ |

Скрипт проверяет каждую карту по размеру и SHA-256, уже скачанные пропускает, прерванную загрузку продолжает,
а если основной сервер недоступен, берёт карту с зеркала MIT. Нужен `curl` (в Windows 10 и новее уже есть).
Можно скачать только нужные карты: программа берёт самую подробную из тех, что покрывают точку.

Источник: набор данных `LRO-L-LOLA-4-GDR-V1.0` (LRO LOLA Gridded Data Records), узел NASA PDS Geosciences
(https://pds-geosciences.wustl.edu/lro/lro-l-lola-3-rdr-v1/lrolol_1xxx/data/lola_gdr/), зеркало
https://imbrium.mit.edu/DATA/LOLA_GDR/.

## Результаты

Каждый запуск пишет в `logs/`:

- `flight-<время>.json` — журнал полёта в читаемом JSON: сводка, космодром, место посадки, этапы, все шаги расчёта;
- `trajectory-<время>.json` — траектория для 3D (формат `lwp-trajectory/1`, описан в [trajectory-format.md](trajectory-format.md)).

## API для других программ

```bash
echo '{"arrival_date":"2027-02-14","spaceport":"baikonur","rocket":"soyuz_21b_fregat","landing_site":{"lat_deg":-89,"lon_deg":45}}' \
  | target/release/launch-window-prediction api submit --wait --pretty
```

Команды `catalog`, `submit`, `status`, `result`, `list`, `delete`, а также форматы запросов и ответов и пример
клиента на Python описаны в [api.md](api.md).

## Ограничения модели

- Траектории: прямой перелёт и перелёт Гомана; другие типы (через точки Лагранжа, с низкой энергией) не
  реализованы. Новый тип добавляется реализацией `LegModel` в `src/trajectory/` (см. `common.rs`).
- Перелёт Гомана: момент разгона привязан к проходу точки напротив Луны на опорной орбите, поэтому время
  полёта совпадает с половиной периода эллипса с допуском `[hohmann] timing_tolerance_min` (расхождение
  компенсируется апогеем и затем доводится до долей секунды). Численное уточнение подбирает разгон с учётом
  притяжения Луны и Солнца, поэтому уточнённый разгон немного отличается от чисто касательного.
- Выход на окололунную орбиту и сход с неё считаются импульсными.
- Не учитываются погода, суточные ограничения на время старта, давление солнечного света и сопротивление атмосферы.
- Посадка на обратную сторону Луны по умолчанию запрещена: нет прямой связи с Землёй. Разрешить можно в
  `data/transfer.toml` (`require_earth_visible = false`); спутник-ретранслятор в модели не учитывается.
- Данные ракет со ступенями есть для SLS, Long March 5, Ariane 62/64, «Союза-2.1б»; для остальных космодромов
  подъём упрощённый.
